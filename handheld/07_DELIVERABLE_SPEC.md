# 07 · 交付规格（HTML）

## 7.1 交付物

**一个自包含的 HTML 文件**（inline CSS + inline SVG，无外部依赖、无 CDN、无脚本），中文正文。
标题建议：`T1 牵手跟随机制拆解：判定 · 切换 · 速度解算`。

内容过长时按 **PART 1/3、2/3、3/3** 分段输出，每段结尾写"下一段将回答……"，不要中途省略。

## 7.2 必须包含的章节

### 0. 答案卡（一页，必须最先出现）

- 三个问题各 **一句话结论**（≤40 字）。
- 一张"三层归属"小图：Action / Runner / Command，标明"牵手"落在哪层。
- "读了哪些文件、没读哪些"声明（诚实优先）。

### 1. Q1 判定与能力归属

- 判定矩阵（判据 × 阈值 × 单位 × 帧数 × 触发的输出 × 证据）。
- 判定时序图（t=0 握手 → 越阈 → 计数 → 上报 → 给速度）。
- "新 runner + 换 kp/kd"假设的逐项裁决表：假设项 / 证据 / 结论（成立/部分成立/不成立）/ 缺件。
- 最小实现集（若要复刻，需要哪些信号、配置、状态、接口）。

### 2. Q2 切换与准入准出

- 准入准出状态机图（IDLE / CANDIDATE / ACTIVE / DECAY / EXIT），边上标条件与时间。
- 动作图 vs runner 子状态的双层对照图：说明"动作切换"与"拖拽状态"是两套东西。
- 时间线：握手 → yaw 响应 → held 上报 → vx 启动 → 稳态（每一段给数字与依据）。
- 异常退出表：松手 / 换动作 / 变形 / 跌倒 / 急停 / 超时，各自走哪条路。
- 仲裁：拖拽 vs 视觉 vs 摇杆 vs TTL。

### 3. Q3 速度解算

- 信号流图（关节 q/dq → FK/偏差 → 死区 → 计数 → 增益 → 限幅 → 斜坡 → obs）。
- 公式表（符号、单位、出处）。
- 参数-语义表（值 / 单位 / 证据级别）。
- 数值例子（手前伸 0.3 m、roll 0.2 rad 时的 vx/yaw 量级）。
- 伪代码（明确"重构，不是源码"）。
- 等效导纳：`F → v` 的等效增益与数量级。

### 4. 证据、反证与未知

- 证据表（S/M/W）。
- 对 `ka/kb`、`push_wheel_threshold`、轮端回路、左右手合并、拖拽 vs 外部速度：每个给 **两种解释 + 判别实验**。
- 明确列出"如果这些实验结果是 A，则支持解释 1；是 B，则支持解释 2"。

### 5. Collie 可复用设计（简短，≤1 页）

- `interaction.hand_held` 能力块（YAML 草案）。
- 三条硬契约：上肢唯一写者；held 由事实产生；拖拽走统一后处理链。
- 5 条验收用例。

### 6. 验证实验清单

- E1–E10：问题 / 操作 / 观测字段 / 判据 / 结论如何写回。

### 附录

- 参数总表（按"检测→解算→整形"排序）。
- 文件索引（每个证据指向仓库路径）。

## 7.3 图表要求

- **至少 3 张图**：判定时序、准入准出状态机、解算信号流。
- 图用 **inline SVG**，不要 mermaid 代码块（网页版渲染不稳定）。
- 图中每个阈值/字段都要能在正文表格里找到出处。

## 7.4 评分（自评，附在最后）

| 维度 | 分值 | 判据 |
|---|---|---|
| 证据纪律 | 30 | 每个结论有出处；推断/未知标注正确；无编造字段 |
| 机制正确性 | 30 | 三层归属、判定链路、解算链路自洽；能解释"为什么不是新 runner" |
| 切换完整性 | 20 | 准入/保持/准出/异常全覆盖；动作层与 runner 层不混 |
| 设计可复用性 | 10 | Collie 映射具体、可落地 |
| 表达 | 10 | 图清晰、结论先行、不堆砌 |

## 7.5 输出协议

1. 开头先写"阅读声明"：实际读了哪些文件、哪些没读、对结论的影响。
2. 每个结论用 `[证据] / [推断] / [未知]` 标注。
3. 引用格式：`文件路径 · 字段名`（例如 `raw/t1/qd1_t2d0/rl/bi_wbc_run.yaml · arm_drag.forward_pos_threshold`）。
4. 不确定就写 `UNKNOWN`，并给"验证方法"，不要猜数字。
5. 不要输出"我将要做什么"的过程叙述；直接给结果。
6. 若 HTML 超长：PART 分段，每段自包含、可单独阅读。

## 7.6 不要做的事

- 不要把 `DAMPING_DEFAULT` 当作牵手模式。
- 不要假设有 F/T 传感器。
- 不要把假设稿当证据复述。
- 不要给"泛泛的架构建议"代替机制分析。
- 不要编造 T1 没有的字段或日志。
